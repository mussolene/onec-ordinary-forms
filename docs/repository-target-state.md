# Целевое состояние репозитория

## Текущая цель: полное покрытие 8.5.1.1343

Целевая платформа: 1С 8.5.1.1343. ActiveXControl явно исключен из приемки.
В справочном каталоге остаются 26 типов, целевых типов 25. Две записи свойств
ActiveX остаются в каталоге, но не участвуют в счетчиках незавершенного
целевого покрытия. Это изменение границы, а не реализация этих свойств.

Для учета используется `oof --coverage --json`. Флаг
`descriptorCoverageComplete` означает завершенность классификации дескрипторов,
а не доказанную сохранность семантики или готовность выпуска.

Приемка 100% требует одновременно:

1. Для каждого целевого свойства и события установлены применимость, доступ,
   сохраняемость, тип значения, default и кодек. Вычисляемые и временные
   свойства явно классифицированы, неизвестных записей нет.
2. Все сохраняемые понятия представлены именованным XML и читаются/записываются
   через объектную модель. Неизвестные данные не заменяются сырыми потоками.
3. Для каждой пары контроль/свойство проверены default, допустимые варианты,
   граничные значения и отказ на неправильном типе; изменения подтверждены
   независимо созданными примерами и платформенными getters.
4. Пройдены строгий Designer, повторный XML/BIN цикл, проверка реального корпуса
   и семантическое сравнение. Успех собственного reader/writer недостаточен.
5. Ошибки записи не оставляют смешанный пакет. Проверка выпуска включает
   перечисленные условия и запрещает объявлять неполную проекцию полной.

## Порядок завершения полного покрытия

Работа идет проверяемыми семействами. Для каждой итерации сначала устанавливается
контракт по API 8.5.1.1343 и собственным платформенным пробам, затем изменяется
именованная модель и кодек. Счетчики уменьшаются только после подтверждения
классификации, а поддержка хранения считается проверенной после независимого
платформенного цикла.

| Пакет работ | Область реализации | Критерий закрытия |
| --- | --- | --- |
| Общие свойства | Существующие дескрипторы, общие кодеки значений и базового блока | У каждого применимого контрола проверены default, явное значение, сброс и исключения; сходство названий не заменяет пробу |
| Свойства отдельных типов | Оставшиеся именованные свойства и enum каждого из 25 контролов | Для каждой записи установлены доступ, сохраняемость, тип и default; сохраняемые значения собираются из XML, временные и вычисляемые явно классифицированы |
| События | Оставшиеся 82 записи, владельцы, обработчики и описание действий | Холодное чтение, назначение и сброс, сохранение после Designer; для событий интерфейса проверена реальная диспетчеризация; неизвестные записи не теряются молча |
| Типы и составные значения | Описания типов, привязки, команды, коллекции, картинки и вложенные объекты | Весь поддержанный граф строится из именованных XML/ресурсов; нет скрытого потока или зависимости от исходного BIN; некорректные ссылки отклоняются |
| Платформенный корпус | Существующие нативные тесты и инструменты строгой проверки | Для каждого сохраняемого свойства есть default и измененный случай, для сочетаний проверяются полный XML, модуль, ресурсы и фактические значения после загрузки; есть тесты неизвестных и поврежденных входов |
| Выпуск | Существующий release-gate, CLI, документация и проверки безопасности | Gate действительно запускает необходимые проверки и падает при пропуске; ASan/UBSan, ограничения ресурсов, безопасная запись и проверка утечек успешны; все критерии приемки имеют свежие доказательства |

Для субагентов используются ограниченные задания по одному семейству и точному
списку файлов. Исследование API и независимое ревью можно выполнять параллельно.
Правки общего form_stream.cpp интегрируются последовательно; платформа и итоговая
сборка запускаются после остановки всех авторов соответствующих файлов. Результат
субагента принимается только после просмотра изменений и независимой проверки.
Каждая завершенная итерация оставляет отдельный коммит, свидетельство и checkpoint.

Незавершенный `make release-gate` и отсутствие автоматического полного корпуса
остаются отдельными блокерами приемки. Нулевые счетчики дескрипторов сами по себе
не закрывают эти блокеры. Публикация допускается только в авторизованный приватный
репозиторий, согласно AGENTS.md.

Проверочные примеры текущей серии хранятся в игнорируемом
`scan-output/full-coverage-20261026/`. Это собственные синтетические данные для
платформенных доказательств; бинарные файлы и журналы не включаются в Git.

## Цель первой версии

Первая полезная версия помогает увидеть и сравнить поддержанные изменения обычной формы в Git. Она читает `Form.bin` в именованную модель, показывает доступные данные в `Form.xml` версии 2.1 и соседнем `Form/Module.bsl`, а затем может собрать новый `Form.bin` из этой модели.

```text
Form.bin -> OrdinaryForm -> Form.xml + Form/Module.bsl
Form.xml + Form/Module.bsl -> OrdinaryForm -> Form.bin
```

Публичный XML описывает только распознанные свойства и значения. Отсутствие diff в XML не доказывает, что исходные формы одинаковы: неподдержанные или неизвестные данные могут не попасть в модель. Это ограничение показывается предупреждениями и `reconstructionComplete="false"`.

Подробное устройство модели и запрет на публикацию сырых данных заданы в [контракте OrdinaryForm](ordinary-form-target-contract.md). История платформенных опытов и детальные evidence refs собраны в [карте исследований](research-map.md); эта страница фиксирует только актуальную рамку работы.

## Ограничения и поведение

- Набор контролов и свойств с доказанным бинарным циклом ограничен. Одна запись в XSD или метамодели не доказывает поддержку кодека.
- Неизвестные свойства не маскируются сырым потоком. Читатель сохраняет именованные данные, которые понимает, и предупреждает о потерях; сборка создает канонический результат из этой проекции.
- Успешная сборка и приемка Designer показывают, что собранный результат читается платформой. Они не доказывают, что все неподдержанные данные исходной формы сохранены.
- Значения по умолчанию и варианты перечислений считаются поддержанными только при наличии проверки. Неизвестное значение нельзя заменять догадкой или молча пропускать.
- Публичный XML не содержит исходные потоки, базовые снимки, индексные записи, бинарные заглушки или альтернативные скрытые модели.

## Ближайшая работа

1. Развивать общие кодеки свойств через существующую метамодель и проверять их применимость у контролов с подтвержденной семантикой. Общие свойства включают `Enabled`, `ToolTip`, `Font` и `BorderColor`; исключения и значения по умолчанию остаются явными для типа.
2. Сначала закрывать свойства, полезные для сравнения, с понятными именами, типами и значениями по умолчанию. Для неподдержанных данных сохранять диагностику и неполноту модели.
3. Продолжать описывать новые значения только после проверки именованного XML, сборки, строгого Designer и повторного чтения на собственном образце.
4. Не расширять release-gate в рамках этой версии сравнения. Выпуск потребует отдельного решения и реальных проверок поставки.

Сведения по семействам свойств и их подтвержденным значениям находятся в [контракте](ordinary-form-target-contract.md#concept-registry), по общим шаблонам - в [аудите паттернов](ordinary-form-pattern-audit.md), по экспериментам - в [карте исследований](research-map.md).
