Статус продукта: **PARTIAL**. Последний полный корпусный замер относится
к коду `ef5dd742f2a002797a1c8c15f396bd93860a5a48`, 12 ноября 2026.
Последующая уборка документации не меняет кодеки и не является новым замером.
Цель: самостоятельная разборка и сборка обычных форм на 8.5.1.1343 Linux,
без ActiveXControl, с сохранением поддержанных данных после редактирования.

## Почему число полных форм не растет

Последняя итерация устранила 181 ложное несовпадение типов метаданных, но
получила те же 80 полных, 192 частичных и 7200 отказов. Исправление открыло
следующие ограничения. Предшествующий этап перевел 33 формы из отказа
в частичные, также без новых полных форм.

Крупнейшие первые отказы текущего замера:

| Первый отказ | Форм |
| --- | ---: |
| Несовпадение с константным контрактом | 1905 |
| Неподдержанная стандартная команда | 540 |
| Другая длина записи | 499 |
| Оболочка редактора колонки Table | 412 |
| Тип источника Table | 352 |
| Идентичность поля колонки в метаданных | 337 |
| Числовой член метаданных без дескриптора | 309 |
| Признак картинки меню | 284 |

Это взаимоисключающие **первые** причины, а не полный перечень проблем
каждой формы и не прогноз прироста. Ранее ограниченная разбивка 1865
константных отказов отнесла 1602 к общей коллекции меню и 182 к выбору
обработчика действия. Ее нельзя складывать с текущей таблицей.
Доказательство разбивки: `ev_814c0a41803d454ca5c8d61afecedae8`.

Вывод и изменение порядка разработки: [архитектурный аудит](ordinary-form-pattern-audit.md),
[единая карта завершения](platform-mechanism-extraction.md#implementation-map).

## Текущие ограничения

- Автоматические коллекции меню и многие стандартные команды.
- Источники Table, старые оболочки колонок и вложенных редакторов,
  разрешение некоторых членов метаданных.
- Другие поколения записей и составных значений; наличие типа в XSD
  не снимает проверок конкретного состояния.
- Непустая коллекция Commands представлена моделью/XML, но writer ее
  отвергает. Меню и обработчики событий имеют отдельные работающие кодеки.
- Полное сохранение исходных поколений компонентов еще не реализовано.
  Исключение с явным контрактом: SpreadsheetDocumentField 14/16/18.
- 14 кодеков состояния выполнения, [#49](https://github.com/mussolene/onec-ordinary-forms/issues/49).
  Старые колонки: [#48](https://github.com/mussolene/onec-ordinary-forms/issues/48).
  ActiveX исключен из цели: [#50](https://github.com/mussolene/onec-ordinary-forms/issues/50).

## Приемка полного покрытия

Все условия обязательны:

1. Каждое сохраняемое понятие целевой области представлено именованной
   моделью, схемой и парой reader/writer. Нет скрытого BIN и сырых записей.
2. Для общих механизмов проверены допустимые состояния, default/явность,
   границы, события, владельцы, вложенность, идентичности и ошибки.
3. Все целевые формы закрепленного корпуса дают полную модель, собираются
   без входного BIN и проходят повторное сравнение XML, модуля и ресурсов.
   Частичные, отвергнутые и пропущенные формы считаются отдельно и не
   исключаются из знаменателя ради успешного показателя.
4. Каждая поддержанная комбинация семейства, поколения и владельца проходит
   независимую проверку Designer, повторное открытие и изменение значений.
   Метаданные и данные стенда соответствуют форме; конфигурация применена
   перед выгрузкой. Собственный roundtrip недостаточен.
5. Ошибки не портят ранее существовавший выходной пакет. Неизвестное значение
   не превращается в default и не удаляется без диагностики.
6. Для требования сохранения исходного поколения оно переживает XML-only
   цикл и допустимые изменения. Непредставимое изменение отвергается до
   записи. Проверка потребителя 8.2 выполняется самой 8.2, отдельно от 8.5.

## Выпуск

Исторический архив `v1.0.0-rc.1` еще допускает сборку неполной проекции.
Для работы используйте текущий `main`; это не объявление стабильного выпуска.
[Манифест](release-evidence.json) описывает предыдущую ограниченную нативную
приемку и привязан к отпечатку исходников. Он не подтверждает текущий main
автоматически. `release-gate` проверяет манифест и переносимые тесты,
но сам не запускает Designer или весь частный корпус.

Порядок проверки кандидата: [разработка](development.md#проверка-кандидата-выпуска).
История измерений: [указатель исследований](research-map.md).
