# Целевое состояние репозитория

## Цель первой версии

Первая полезная версия помогает увидеть и сравнить поддержанные изменения обычной формы в Git. Она читает `Form.bin` в именованную модель, показывает доступные данные в `Form.xml` версии 2.1 и соседнем `Form/Module.bsl`, а затем может собрать новый `Form.bin` из этой модели.

```text
Form.bin -> OrdinaryForm -> Form.xml + Form/Module.bsl
Form.xml + Form/Module.bsl -> OrdinaryForm -> Form.bin
```

Публичный XML описывает только распознанные свойства и значения. Отсутствие diff в XML не доказывает, что исходные формы одинаковы: неподдержанные или неизвестные данные могут не попасть в модель. Это ограничение показывается предупреждениями и `reconstructionComplete="false"`.

Подробное устройство модели и запрет на публикацию сырых данных заданы в [контракте OrdinaryForm](ordinary-form-target-contract.md). История платформенных опытов и детальные evidence refs собраны в [карте исследований](research-map.md); эта страница фиксирует только актуальную рамку работы.

## Текущее подтвержденное состояние

- 25 из 25 минимальных проверенных типов проходят нативный XML/BIN цикл. Это набор минимальных примеров, а не доля полной поддержки продукта. Свидетельства: `ev_884546e4c64c4278aca8b4e8421f0f31`, `ev_74c90b8b08664bfdbcb3439a57c723af`.
- Все 38 контролов эталонной формы читаются. Именованная проекция собирается без исходного BIN и проходит строгую выгрузку Designer; XML, модуль и повторный BIN собственного writer совпадают. Исходное чтение выдает 63 предупреждения OOF1140 и `reconstructionComplete=false`. Полное восстановление произвольной формы не подтверждено. Свидетельство: `ev_87eeb5b904f74e03b7392b2bb3692d34`.
- macOS и Linux прошли по 11 из 11 тестовых наборов в текущем цикле изменения общих кодеков. Свидетельства: `ev_884546e4c64c4278aca8b4e8421f0f31`, `ev_74c90b8b08664bfdbcb3439a57c723af`.
- Для `LabelDecoration.Font` используется общий `FontValue` и общий кодек свойств контрола. Проверены строгий Designer, повторные XML/модуль/BIN и значение getter. Свидетельство: `ev_7b3b800f167242b8ae4db92c867390e2`.
- `release_ready=false`. Release-gate остается незавершенной заглушкой; релиз и теги не являются частью текущей работы.

## Ограничения и поведение

- Набор контролов и свойств с доказанным бинарным циклом ограничен. Одна запись в XSD или метамодели не доказывает поддержку кодека.
- Неизвестные свойства не маскируются сырым потоком. Читатель сохраняет именованные данные, которые понимает, и предупреждает о потерях; сборка создает канонический результат из этой проекции.
- Успешная сборка и приемка Designer показывают, что собранный результат читается платформой. Они не доказывают, что все неподдержанные данные исходной формы сохранены.
- Значения по умолчанию и варианты перечислений считаются поддержанными только при наличии проверки. Неизвестное значение нельзя заменять догадкой или молча пропускать.
- Публичный XML не содержит исходные потоки, базовые снимки, индексные записи, бинарные заглушки или альтернативные скрытые модели.

## Ближайшая работа

1. Развивать общие кодеки свойств через существующую метамодель и проверять их применимость у контролов с подтвержденной семантикой. Общие свойства включают `Enabled`, `ToolTip`, `Font` и `BorderColor`; исключения и значения по умолчанию остаются явными для типа.
2. Сначала закрывать свойства, полезные для сравнения, с понятными именами, типами и значениями по умолчанию. Для неподдержанных данных сохранять диагностику и неполноту модели.
3. Продолжать описывать новые значения только после проверки именованного XML, сборки, строгого Designer и повторного чтения на собственном образце.
4. Не расширять release-gate в рамках этой версии сравнения. Выпуск потребует отдельного решения и реальных проверок поставки.

Сведения по семействам свойств и их подтвержденным значениям находятся в [контракте](ordinary-form-target-contract.md#concept-registry), по общим шаблонам - в [аудите паттернов](ordinary-form-pattern-audit.md), по экспериментам - в [карте исследований](research-map.md).
