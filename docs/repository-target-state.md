# Текущее состояние и приемка

## Быстрый путь

Сценарий использования: `oof dump Form.bin Form.xml`, просмотр/правка XML,
BSL и ресурсов в Git, затем `oof build Form.xml Form.bin` и независимая
проверка Designer. Исходная база и исходный BIN для сборки не нужны.
[Быстрый старт](../README.md#быстрый-старт),
[точки интеграции CLI и C++](development.md),
[контракт модели](ordinary-form-target-contract.md),
[карта реализации по SO/DLL и критерии приемки](platform-mechanism-extraction.md#implementation-map).

## Цель и текущие ограничения

Цель полного покрытия сохраняется: 1С 8.5.1.1343, Linux, 25 типов контролов.
ActiveXControl явно исключен из этой целевой области и остается в справочном
каталоге из 26 типов. Исключение не является реализацией ActiveX.

Текущий `oof --coverage --json`:

| Остаток классификации | Количество |
| --- | ---: |
| Свойства | 0 |
| События | 0 |
| Значения по умолчанию | 0 |
| Кодеки хранения | 0 |
| Виды значений | 0 |
| Кодеки живых значений | 14 |

`descriptorCoverageComplete=false`. Даже нулевой остаток классификации
не доказывает полноту сериализации или сохранность реальной формы.
`reconstructionComplete="false"` и предупреждения означают неполную проекцию;
неизвестные исходные данные не восстанавливаются из скрытого baseline.

Открытые контракты работ:

- [#48: старые колонки, редакторы и источники Table](https://github.com/mussolene/onec-ordinary-forms/issues/48).
- [#49: 14 живых значений, типы и владение объектами](https://github.com/mussolene/onec-ordinary-forms/issues/49).
- [#50: ActiveX, CLSID/State и Windows/Linux](https://github.com/mussolene/onec-ordinary-forms/issues/50).

У каждой задачи есть исходные факты, границы, положительные и отрицательные
проверки, платформенная приемка и ссылки на конкретный коммит. Реальный корпус
пока не имеет полного положительного результата. Полная цель не завершена.

### Проверенная граница на 2026-11-12

В `main`, коммит `9b027c3`, CLI не записывает неполный пакет, а writer
отклоняет неполную модель и требует полного повторного чтения результата.
Реальная форма с изменением Caption и AutoTitle прошла самостоятельную
сборку, загрузку Designer и строгую выгрузку с полным сравнением XML и модуля.
Прошли 12 групп тестов; отдельный набор из 12 панелей с 36 действиями
совпал с нативным эталоном. Свидетельства: `ev_7aab653fe4a24ddbbc09d02a87b84345`,
`ev_bbb5c144852542f1b5dec7b3369ddfed`.

В ограниченной выборке десяти ранее проблемных форм остались три неполные
модели и семь отказов в шести группах: настройки ссылочного InputField,
старые колонки Table, оболочка редактора Table, неявный Text меню,
вариант записи реквизита и границы владельца. Выходные файлы при отказах
не изменились. Это проверка защиты от потерь, не приемка полного корпуса.

Новое требование сохранять исходные версии компонентов формы пока не
выполнено: writer выбирает современные версии, а модель и XML не передают
исходные. Проверка текущего кода и библиотек:
`ev_9465e7269bab4356b25431b755ca656b`.

Основной цикл исправлений и независимой приемки использует 8.5.1.1343.
Образ 8.2 под Wine сохранен для отдельной проверки совместимости;
исторический вариант writer 8.2 не является текущей реализацией.

### Общие кодеки и свежая приемка, 2026-11-12

Исправлены смешанные поколения значений колонок и базы ChoiceField,
добавлены четыре именованных параметра редактора формы, чтение boundary1
и ограниченного root owner18. Основной реквизит и контроллер расширения
теперь сохраняются независимо. Зарегистрированы три пустых расширения списков;
это не означает поддержки всех источников их табличных полей.

Полная сборка и 12 тестовых групп прошли. Для двух матриц по 11 форм
и 100 контролов исходные BIN удалены перед обратной сборкой. Строгий Designer
подтвердил Load/Save, все XML и модули совпали:
`ev_eceb6e9994da4e17b80237bc0c26297f`. Отдельно проверены 12 смешанных колонок
(`ev_0d29d705dd3a4f8cbe02c30bba90e7c7`) и 10 вариантов параметров редактора
(`ev_f22bafe6f9b344539048cc4ec6b50e6e`).

Проход всего корпуса с контекстом соответствующей конфигурации дал:

| Результат чтения | Форм |
| --- | ---: |
| Полная модель и именованный XML | 75 |
| Неполная модель | 162 |
| Отказ | 7235 |
| Всего | 7472 |

Это проверка чтения и сериализации XML, не нативная приемка всего корпуса.
Отчет: `scan-output/corpus-closure-20261112/aggregate.json`.
Следующие общие ограничения: поля и оформление старого корневого владельца
(1484 первичных отказа), источники Table (848), остальные версии записей,
порядок обхода и контекстные связи. Указанные группы не следует складывать
с историческими результатами или считать независимыми свойствами формы.

Необъясненное владение реквизитом и переводы подменю остаются явными отказами.
Нативные контрпримеры показали, что их очистка меняет поведение:
`ev_4df51acb60064198b25871a9e3329e46`, `ev_0ab871222b3241d09cfe32e7db3a4a9f`.
Цель полного корпуса остается незавершенной.

### Исторические результаты корпуса и отдельных семейств

Следующие результаты относятся к более ранним итерациям. Они не являются
свежим измерением покрытия `9b027c3` или более позднего кода.

Исторический полный проход по 7472 обычным формам из двух разрешенных
эталонов дал 34 проекции с `reconstructionComplete=true`, 29 частичных и
7409 отвергнутых, без ошибок чтения и без извлечения модулей.
Свидетельство прохода: `ev_64cb56a3319e4c4aa1f886930808a863`.
Это результат чтения. Отдельная обратная сборка и проверка Designer всех
34 полных проекций еще не выполнены, поэтому эти числа не означают
полную приемку форм.

Крупнейшие первые отказы: несовпадение констант записи (1657), арность
записей (1249), неподдержанные источники Table (685), поле 6 старого
корневого владельца (592), порядок обхода контролов (457), структурная
форма записи (396), стиль действия (328), расширение формы (305) и поле 4
старого корневого владельца (296). Декодер останавливается на первом отказе;
эти группы не являются исчерпывающим списком недостающих понятий внутри
каждой формы. Прежняя выборка первых 512 форм дала 512 отказов, но ее
распределение причин не отражало весь корпус.

Два новых расширения списков проверены на собственных формах, по десять
разных типов контролов в каждой. Проверены сборка без дерева конфигурации,
открытие через `GetForm`, строгая выгрузка Designer, сборка только из XML
и повторные открытие и строгая выгрузка пересобранных файлов. Именованная
модель и модули сохраняются с учетом имени формы из метаданных и добавляемого
платформой значения `LabelDecoration.HorizontalAlign=Left`. Текущие результаты:
`scan-output/list-extension-native-20261111/acceptance-summary.txt`.
Это приемка двух расширений, а не полного набора свойств форм списка.

`DocumentFormExtension` поддерживает четыре сохраняемых свойства,
четыре события и поколения настроек 0-4. Нативная матрица десяти собственных
форм со ста контролами прошла исходный и XML-only цикл с точными сравнениями
свойств, обработчиков, модулей и именованной модели:
`ev_ed9abac091714b12bbf7268718751805`. Все 12 текущих переносимых тестов
прошли: `ev_ae61b11058044d7dbcdf1f97d1fd59d7`.
В реальном корпусе 616 форм прошли прежний отказ неизвестного расширения,
две дополнительные формы получены как частичные модели. Число полных
проекций не увеличилось; следующие ограничения остаются явными отказами.

На собственном наборе меню все 198 пар исходной и нативно сохраненной
формы дали одинаковые XML и модули. Из них 165 проекций полные и проходят
сборку из XML; 33 старых CommandBar остаются неполными из-за независимого
второго контекста, который еще не представлен именованным свойством.
Этот результат не переносится на реальный корпус и не закрывает кодек меню.

Старые записи свойств LabelDecoration поколения 7 и оформления картинки
поколения 3 теперь читаются через независимые таблицы форматов. Приемка
14 собственных форм с 50 контролами прошла строгий Designer и точное
сравнение XML/модулей. В полном корпусе 40 форм прошли прежний отказ арности
и дошли до следующих ограничений; число полностью разобранных форм пока
не увеличилось. Это исправление не является приемкой всего корпуса.

Для Table существуют отдельные семейства источников. Текущий кодек содержит
именованные источники ValueTable, ValueTree и расширение списка документов
с отдельными ограничениями. Произвольный объектный GUID не делает источник
поддержанным: 685 форм полного прохода остановились на неподдержанном
источнике Table. У допущенных источников также остаются ограничения колонок
и вложенных редакторов. Нулевые счетчики классификации не закрывают эти
пробелы форматов.

## Предварительный выпуск

Версия `1.0.0-rc.1` является историческим предварительным выпуском.
Она еще допускает сборку неполной проекции и не содержит защиты от потерь
из `9b027c3`. Для текущей работы следует собирать `main`, соблюдая указанные
ограничения. Полная приемка и сохранение исходных версий пока не завершены.

`make release-gate RELEASE_TAG=v1.0.0-rc.1` собирает продукт, заново выполняет
CTest и smoke, проверяет версию CLI, фактические счетчики и
[манифест доказательств](release-evidence.json). Манифест привязан к отпечатку
исходников и описывает нативную проверку; он не заменяет ее выполнение.
Изменение исходников требует обновленного подтверждения. Стабильный выпуск
не допускается при незавершенной приемке корпуса и открытых ограничениях.

[Workflow Release](https://github.com/mussolene/onec-ordinary-forms/blob/v1.0.0-rc.1/.github/workflows/release.yml) публикует Linux x86_64,
схемы, документацию, исходный пример и контрольные суммы. Сборка связана
динамически с libxml2, zlib и ICU; требования к среде указаны в README.

## Приемка полного покрытия

Все условия обязательны одновременно:

1. Для каждого целевого свойства и события подтверждены применимость, доступ,
   сохраняемость, тип, default и кодек. Вычисляемые и временные свойства
   классифицированы; неизвестных записей нет.
2. Все сохраняемые понятия представлены именованной моделью и XML.
   Сборка выполняется без исходного BIN, сырых потоков, индексных записей
   и патчей исходной формы.
3. Для каждой пары контроль/свойство проверены default, допустимые варианты,
   границы и неправильный тип. Значения подтверждены независимыми примерами
   и платформенными getters.
4. Пройдены строгий Designer, повторный XML/BIN цикл, реальный корпус и
   семантическое сравнение. Успех собственного reader/writer недостаточен.
5. Ошибки записи не оставляют смешанный пакет. Проверка выпуска учитывает
   предыдущие условия и не объявляет неполную проекцию полной.
6. Самостоятельный пакет хранит целевые версии компонентов. Без изменений
   и после допустимых изменений сборка сохраняет их; непредставимое значение
   отклоняется до записи. Повышение версии не происходит автоматически.
   Старые поколения проверены также соответствующей старой платформой.

Платформенные проверки общих механизмов объединяются в пакеты минимум
по десять контролов. Полная корпусная приемка выполняется после завершения
семейств и перед выпуском; подробная матрица описана в карте реализации.
