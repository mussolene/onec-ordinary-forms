# Целевое состояние репозитория

Цель проекта: простая утилита для чтения, редактирования и сборки обычной формы как объектной модели с именованным XML 2.1 и отдельным `Module.bsl`. Словарь XML проекта вдохновлён читаемостью управляемых форм, но не совместим с форматом их выгрузки. Утилита не считается универсальной, пока фактическое покрытие бинарного кодека не подтверждено.

## Единственный продуктовый путь

```text
Form.bin -> OrdinaryForm -> Form.xml + Form/Module.bsl
Form.xml + Form/Module.bsl -> OrdinaryForm -> Form.bin
```

`OrdinaryForm` владеет объектами, идентификаторами, свойствами, значениями, событиями, элементами и модулем. `Form.bin` является форматом хранения. Если значение ещё нельзя собрать, добавьте именованное свойство или тип и его кодек в обычный путь, после чего зафиксируйте проверку. Не публикуйте низкоуровневые записи, сырые потоки или сохранённый бинарный профиль в XML.

### Волна 2. Исправление общего рабочего пути

1. Интегратор принимает результаты волны 1 и закрепляет непересекающиеся
   компоненты за исполнителями. Общие диагностические функции, диспетчер
   чтения и архитектурные решения остаются у интегратора.
2. Исполнитель typed_fields исправляет ChoiceField и редакторы Table.
   Непредставленные свойства не блокируют доступные имена, привязки и данные.
   Неверные GUID, счетчики, типы, поврежденный сжатый пакет и ссылки остаются
   ошибками. Неизвестное оформление не превращается в числовое свойство XML.
3. Исполнитель complex_gaps исправляет только чтение сложных коллекций и
   обработку неподдержанных свойств. Идентичности, число элементов, связи,
   типизированные значения и матрицы проверяются строго. Данные не заменяются
   пустыми коллекциями для получения успешного результата.
4. Отдельный исполнитель реализует общий API свойств после принятия проекта
   property_api. Владение: ordinary_form.hpp/cpp и собственные тесты модели.
   Расширение метамодели согласуется отдельно; storage-файл ему не принадлежит.
5. Интегратор собирает изменения последовательно, выполняет текущие тесты и
   полный цикл эталона. Затем contract_audit повторяет проверку независимо.

Критерий выхода волны 2: AC2-AC4 подтверждены; AC1 проверен в измененной
области. При новом отказе фиксируется конкретный непройденный критерий,
а задача возвращается владельцу с воспроизведением. Переход к следующей
волне не означает готовности выпуска.

### Волна 3. Полное покрытие по семействам

1. Сформировать из исполняемой метамодели список уникальных свойств, событий
   и defaults с применимостью к контролам. Число вхождений не считать числом
   независимых механизмов. Сначала общие Color/Font/Border/Picture, состояние,
   геометрия, типы и привязки; затем исключения конкретных контролов.
2. На каждое семейство назначать одного исполнителя. Он устанавливает
   именованную семантику и соответствие хранению собственным опытом,
   расширяет существующий общий кодек, проверяет несколько владельцев.
3. Отдельные зависимые задачи: Commands и события с доказанными владельцами;
   типы и свойства вложенных редакторов; содержимое и оформление сложных
   контролов; неизвестные общие значения ClientOSInfo.
4. Для ClientOSInfo сначала обеспечить разрешенную компиляцию собственного
   диагностического кода. До этого неизвестные имена значений остаются
   UNKNOWN. Повторять заблокированные загрузки платформенных библиотек
   в сторонний контейнер нельзя.
5. После каждого принятого семейства обновлять реальное покрытие и проводить
   строгий цикл собственного непустого образца. Полный эталон должен пройти
   без потери исходных поддерживаемых значений и без неполноты восстановления.

Критерий выхода волны 3: AC1 и AC5 PASS. Исследование общего поля проводится
один раз, его применение к другим типам проверяется матрицей исключений.

5. Опубликовать проверенные коммиты и обновить текущие PR после разрешения

### Правила исполнения

- Все исполнители используют существующие владельцы модели, XML, схем и
  кодеков. Перед новой возможностью обязательна ReuseDecision.
- Общий build и лицензированная платформа используются последовательно
  через интегратора. Две параллельные сборки одного каталога запрещены.
- В совместных файлах закрепляются конкретные функции и области; общие
  сигнатуры и вызовы меняет интегратор. Не создавать дополнительные ветки
  или worktree без необходимости.
- Исполнители не делают commit, push, публикацию, установку инструментов,
  изменение разрешений и создание новых агентов без назначения интегратора.
- Приватный эталон используется только в разрешенной области; в вывод,
  документацию и OACS попадают счетчики, типы, коды и обезличенные пути ошибок.
- Результат задания содержит changed scope, собственные проверки, evidence,
  непройденные AC и точный следующий шаг. После сдачи исполнитель завершает
  работу. Итоговый checkpoint стабильной задачи записывает интегратор.
- Изменение AGENTS.md, существовавшее до этой работы, не включается в коммиты.

### Текущая проверка минимальных профилей

На 2026-10-05 независимо проверены 25 минимальных профилей, по одному на каждый
целевой тип без ActiveX. После исправления вычисляемых значений пустой Chart

Это 100% по проверенным минимальным профилям, а не по всем свойствам.

событий, вложенности или состояния каждого контрола без реквизитов.

## Ближайшие этапы

Текущий план на 2026-10-04 строится по общим механизмам, а не по повторному
разбору каждого свойства каждого контрола. Охват составляет 25/25 PARTIAL,
0 FULL. Подробные общие структуры и ограничения:
[аудит](ordinary-form-pattern-audit.md#общие-механизмы-и-границы-обобщения-2026-10-04).

1. Общие значения: переиспользовать кодеки Font, Color, Picture и строк.
   Для каждого нового владельца устанавливать место свойства, defaults и
   ограничения, затем проверять совместную форму нескольких типов.
