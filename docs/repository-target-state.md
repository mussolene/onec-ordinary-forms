# Текущее состояние и приемка

## Быстрый путь

Сценарий использования: `oof dump Form.bin Form.xml`, просмотр/правка XML,
BSL и ресурсов в Git, затем `oof build Form.xml Form.bin` и независимая
проверка Designer. Исходная база и исходный BIN для сборки не нужны.
[Быстрый старт](../README.md#быстрый-старт),
[точки интеграции CLI и C++](development.md),
[контракт модели](ordinary-form-target-contract.md).

## Цель и текущие ограничения

Цель полного покрытия сохраняется: 1С 8.5.1.1343, Linux, 25 типов контролов.
ActiveXControl явно исключен из этой целевой области и остается в справочном
каталоге из 26 типов. Исключение не является реализацией ActiveX.

Текущий `oof --coverage --json`:

| Остаток классификации | Количество |
| --- | ---: |
| Свойства | 0 |
| События | 0 |
| Значения по умолчанию | 0 |
| Кодеки хранения | 0 |
| Виды значений | 0 |
| Кодеки живых значений | 14 |

`descriptorCoverageComplete=false`. Даже нулевой остаток классификации
не доказывает полноту сериализации или сохранность реальной формы.
`reconstructionComplete="false"` и предупреждения означают неполную проекцию;
неизвестные исходные данные не восстанавливаются из скрытого baseline.

Открытые контракты работ:

- [#48: старые колонки, редакторы и источники Table](https://github.com/mussolene/onec-ordinary-forms/issues/48).
- [#49: 14 живых значений, типы и владение объектами](https://github.com/mussolene/onec-ordinary-forms/issues/49).
- [#50: ActiveX, CLSID/State и Windows/Linux](https://github.com/mussolene/onec-ordinary-forms/issues/50).

У каждой задачи есть исходные факты, границы, положительные и отрицательные
проверки, платформенная приемка и ссылки на конкретный коммит. Реальный корпус
пока не имеет полного положительного результата. Полная цель не завершена.

Полный разбор 7472 обычных форм из двух разрешенных эталонов текущим
декодером после исправления поколений меню 6/7/8 и старых записей
LabelDecoration дал 1 проекцию
с `reconstructionComplete=true`, 3 частичные и 7468 отвергнутых, без ошибок
чтения и без извлечения модулей. Свидетельство текущего прохода:
`ev_aa39d34379404db09af49278780d7b54`.
Даже единственная полная проекция еще не подтверждена обратной сборкой
и проверкой Designer в этой итерации, поэтому это не результат полной
приемки формы.

Первые причины отказа по всему корпусу: арность записей (2375),
GUID расширений формы (2297), несовпадение констант контракта (876),
источники Table (450), непредставленные поля корневого владельца и его
общей базы (420), остальные варианты (1050). Декодер останавливается на первом отказе; эти группы
не являются исчерпывающим списком недостающих понятий внутри каждой формы.
Прежняя выборка первых 512 форм дала 512 отказов, но ее распределение
причин не отражало весь корпус.

На собственном наборе меню все 198 пар исходной и нативно сохраненной
формы дали одинаковые XML и модули. Из них 165 проекций полные и проходят
сборку из XML; 33 старых CommandBar остаются неполными из-за независимого
второго контекста, который еще не представлен именованным свойством.
Этот результат не переносится на реальный корпус и не закрывает кодек меню.

Старые записи свойств LabelDecoration поколения 7 и оформления картинки
поколения 3 теперь читаются через независимые таблицы форматов. Приемка
14 собственных форм с 50 контролами прошла строгий Designer и точное
сравнение XML/модулей. В полном корпусе 40 форм прошли прежний отказ арности
и дошли до следующих ограничений; число полностью разобранных форм пока
не увеличилось. Это исправление не является приемкой всего корпуса.

Отдельный структурный разбор таблиц в этой выборке обнаружил 555 элементов:
23 с источником ValueTable, 8 с ValueTree, 8 со СпискомЗначений и 516
с объектным типом, заданным GUID. Это учет источников всех найденных таблиц,
а не распределение первых отказов. Текущий кодек допускает только первые
два типа источников. Справка платформы 8.5.1.1343 подтверждает самостоятельное
расширение табличного поля списка значений, помимо расширений списков,
табличных частей и наборов записей конфигурации. Ограничения требуют общих
кодеков и именованных понятий модели; нулевые счетчики классификации их
не закрывают.

## Предварительный выпуск

Версия `1.0.0-rc.1` предназначена для работы в подтвержденной области,
с явно опубликованными ограничениями. Это не утверждение о 100% покрытии.

`make release-gate RELEASE_TAG=v1.0.0-rc.1` собирает продукт, заново выполняет
CTest и smoke, проверяет версию CLI, фактические счетчики и
[манифест доказательств](release-evidence.json). Манифест привязан к отпечатку
исходников и описывает нативную проверку; он не заменяет ее выполнение.
Изменение исходников требует обновленного подтверждения. Стабильный выпуск
не допускается при незавершенной приемке корпуса и открытых ограничениях.

[Workflow Release](https://github.com/mussolene/onec-ordinary-forms/blob/v1.0.0-rc.1/.github/workflows/release.yml) публикует Linux x86_64,
схемы, документацию, исходный пример и контрольные суммы. Сборка связана
динамически с libxml2, zlib и ICU; требования к среде указаны в README.

## Приемка полного покрытия

Все условия обязательны одновременно:

1. Для каждого целевого свойства и события подтверждены применимость, доступ,
   сохраняемость, тип, default и кодек. Вычисляемые и временные свойства
   классифицированы; неизвестных записей нет.
2. Все сохраняемые понятия представлены именованной моделью и XML.
   Сборка выполняется без исходного BIN, сырых потоков, индексных записей
   и патчей исходной формы.
3. Для каждой пары контроль/свойство проверены default, допустимые варианты,
   границы и неправильный тип. Значения подтверждены независимыми примерами
   и платформенными getters.
4. Пройдены строгий Designer, повторный XML/BIN цикл, реальный корпус и
   семантическое сравнение. Успех собственного reader/writer недостаточен.
5. Ошибки записи не оставляют смешанный пакет. Проверка выпуска учитывает
   предыдущие условия и не объявляет неполную проекцию полной.
