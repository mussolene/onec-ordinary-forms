# Указатель исследований

Текущие решения находятся в [архитектуре](architecture.md),
[контракте](ordinary-form-target-contract.md), [статусе](repository-target-state.md)
и [карте завершения](platform-mechanism-extraction.md#implementation-map).
Этот указатель помогает найти доказательство, но не вводит второй план работ.

## Как восстановить контекст

Для существенной задачи используется установленный навык OACS. Логический
выбор проекта: `--db @project`; физическая база и ключи вручную не читаются.

```sh
acs integrations context --intent repo_development \
  --query "точная текущая задача и семейство объекта" --json
acs evidence inspect ev_b55fe9bfe660477cb107142b51de2959 --db @project --json
```

Checkpoint восстанавливает последнюю задачу, историческая память дает
основания. Новая инструкция пользователя важнее обоих. Старый результат
не становится текущим от повторного извлечения памяти. Перед утверждением
о текущем поведении проверяются код и относящаяся к нему команда.

После изменения поведения фиксируются короткое evidence и checkpoint.
В долговечную память переходят только принятые знания с непустыми
`evidence_refs`. Подробные отчеты остаются в игнорируемом `scan-output/`;
частные пути, модули, формы, лицензии и секреты не записываются в OACS.
